# Implementation Contract — Marcelina Miani Portfolio

**This file is the frozen interface contract. Everything here is normative.**
Companion docs: `docs/project-plan.md` (what the experience must do), `docs/css-style-ruleset.md` (visual language).

---

## 0. Non-negotiable technical decisions

| Decision | Value | Why |
|---|---|---|
| Stack | Vanilla **HTML + CSS + JS**. No framework, no bundler, no npm deps. | Must run by double-clicking `index.html` (`file://`) AND from a local server. |
| JS loading | **Classic `<script defer>` tags**, ordered. NO ES modules, NO `import`/`export`. | `file://` blocks ES modules and `fetch()`. Classic scripts work everywhere. |
| Namespace | Single global `window.MP`. Every module attaches to it. **Declare with `MP.x = (function(){...})()` pattern; never `const` at top level without attaching.** | Prevents globals soup, keeps `file://` compatibility. |
| Content | `data/content.js` (text/structure) + `data/media-manifest.js` (generated image lists). | Content is separate from presentation (plan §42). |
| Scrolling | **Native scroll only.** No scroll-hijacking, no virtual scroll. Smoothness comes from damped interpolation of *element transforms*, never from moving the page itself. | Plan §7 — must not break accessibility, touch, or native behaviour. |
| Image fit | Fixed `aspect-ratio` container + `object-fit: cover`. Never rely on source dimensions. | Plan §37 — no layout shift with unknown images. |
| Motion | Single rAF loop in `scroll.js`. No per-element scroll listeners. | Plan §6 — centralised scroll controller. |
| Responsive units | `svh`/`dvh`/`lvh` with `vh` fallback. | Plan §8. |

**Global failure rule:** any missing/unloadable media must render a pastel placeholder *at the same layout size*. Nothing may collapse or break.

## 5. `data/media-manifest.js` — schema (`window.MP_MEDIA_MANIFEST`)

Generated by `tools/build-manifest.js`. Never hand-edited.

```js
window.MP_MEDIA_MANIFEST = {
  generatedAt: "2026-09-15T00:00:00.000Z",
  hero:      { files: ["portrait.png"] },
  contact:   { files: ["portrait.png"] },
  categories:{ "pixel-art": ["pixel-art.jpg"], /* … */ },
  projects:  { "pixel-art": { "pixel-art-canopy": ["01.jpg","02.jpg","03.jpg"], /* … */ } }
};
```

Rules:
- Scan `assets/img/hero`, `assets/img/contact`, `assets/img/categories`, `assets/img/projects/<cat>/<project>`.
- Keep only real image/video extensions: `.jpg .jpeg .png .webp .avif .gif .svg .mp4 .webm .mov`.
- Ignore files starting with `_` or `.`.
- Sort with **natural sort** (`01`, `02`, `10` order, not `1,10,2`).
- Values are **bare file names**; the containing folder is implied by the bucket key. `MP.data` is responsible for building the real path: `assets/img/hero/<file>`, `assets/img/contact/<file>`, `assets/img/categories/<file>`, `assets/img/projects/<categoryId>/<projectId>/<file>`. Always forward slashes.

## 6. Media model (plan §18)

`MP.data` normalises every media entry into one shape:

```js
{
  type: "image" | "video" | "youtube" | "external",
  src:   "assets/img/projects/…/01.jpg",   // resolved, forward slashes
  poster: "assets/img/…/poster.jpg" | null,
  alt:   "…",
  title: "…" | null,
  href:  "https://…" | null
}
```

Type inference (in this order):
1. `youtube` — src matches `youtube.com/watch?v=`, `youtu.be/`, `/embed/`, `/shorts/` → converted to `https://www.youtube-nocookie.com/embed/{id}`.
2. `video` — extension `.mp4 .webm .mov .m4v .ogv`.
3. `external` — absolute `http(s)://` URL that is not a direct media file.
4. `image` — everything else.

**Effective project media resolution order** (`MP.data.mediaFor(categoryId, project)`):
1. Manifest files for `projects/<categoryId>/<projectId>/` (each becomes an `image` or `video` by inference).
2. Else the project's own `media` array from `content.js` (supports `{type, src, ...}` objects **and** bare strings).
3. Else a single synthetic item `{ type: "placeholder", label: project.title }`.

`placeholder` and every load error render `assets/img/_placeholder.svg` with the item label overlaid — inside the same `aspect-ratio` box, so layout never shifts.

### `MP.scroll` — the engine
```
init()                              // builds scene registry from [data-scene], starts the single rAF loop
refresh()                           // re-measure after DOM/layout changes (portfolio.js calls this)
add(cb) -> off()                    // cb(ctx) each frame
progress(id) -> number              // 0..1 for a scene id ('hero' | 'explorer' | 'portfolio:<catId>' | 'contact')
phase(id, {inEnd=0.38, outStart=0.68}) -> { progress, enter, exit, visible, presence, dim }
current() -> id|null                // dominant scene id
to(id, {offset=0, behavior})        // smooth anchor scroll, respects reduced motion
y -> number                         // raw scrollY (read-only mirror)
smoothed -> number                  // damped scrollY
velocity -> number                  // px/frame, damped
direction -> 1|-1
```

Scene progress definition (single source of truth):
`p = (viewportBottom - sceneTop) / (viewportHeight + sceneHeight)`, clamped 0..1.
Scene ids: hero → `'hero'`, explorer → `'explorer'`, each portfolio section → `'portfolio:<categoryId>'`, contact → `'contact'`.
**Animations read `p` (or damped `p`) and interpolate — no one-shot IntersectionObserver reveals.**

### `MP.categories`
```
init()     // builds islands + works menu; returns void
presets -> [ …7 organic blob presets … ]
```
Island behaviour: hover lifts 1.02 + shadow (desktop only, gated by `(hover:hover)`), click → `MP.scroll.to(id)` and **does not** rely on the default anchor jump. Keyboard: native `<a>` focus + Enter. Cursor influence is a ±6px max offset applied in the rAF loop, disabled on touch and reduced motion. Idle drift is `MP.motion.float`, gated off for reduced motion.

Island `x`/`y` are **intent, not geometry**. The field's height comes from the viewport height while the islands take their size from the field's own area, so `categories.js` re-resolves the scatter every time the field rect changes: it fits each silhouette to the field, restores the authored spots, then settles overlapping pairs apart until the blobs sit close without merging. `--island-x`, `--island-y` and `--island-w` are the published result (see §9). At ≤600px `scenes.css` flows the islands into a wrapped CSS stack and the module steps aside.

## 9. Blob preset contract

Seven presets live in `assets/js/categories.js` as `MP.categories.presets`. Each:
```js
{ id: "blob-01", path: "M… Z", viewBox: "0 0 200 200", size: "lg", rot: -4 }
```
`MP.categories.init()` renders one `<clipPath id="blob-01" clipPathUnits="objectBoundingBox">` per preset into `[data-blob-defs]`, with the path normalised to a 0–1 unit box. Islands then use `clip-path: url(#blob-01)`.
Requirements: 7 distinct hand-authored organic paths, visually varied and none of them an oval (one lobed rock, one soft cloud pebble, one lobed rounded-square, one wide cushion pebble, one kidney bean, one teardrop, one squared blob with a bite), each built from **cubic (C) segments only** — no straight-line polygons, no L/H/V/A output — and each staying inside its unit box so nothing crops off-frame. Every preset also fills its box (the path is fitted to it), so the silhouette is as large as its island slot allows.

Every preset must also be a **single smooth closed loop**: no cusps, no petal tips, no spikes. A shape that comes to a point reads as a star beside the round presets, so each preset is generated from a smooth radius profile and the whole loop turns by only a few degrees per step.

Islands may never pile up. `categories.js` measures each preset once to get `rho` — the furthest the silhouette reaches from its centre — and treats each island as a circle of `rho × width`. Because that circle contains the shape at any rotation, keeping two circles apart is a proof the two blobs cannot swallow each other. The layout sizes the cluster against the field's own area (bisecting for the largest size that still resolves) and reserves a small separation band for the idle float, hover lift and cursor nudge, so the shapes come to rest touching or a few px apart — close and organic, never merged.
